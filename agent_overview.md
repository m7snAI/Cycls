config that drive it). This document focuses on the **serving layer** — the Cycls
chat agent that reads tender data and talks to users. It does not re-document the

them (the `search_tenders` RPC and the Supabase schema it reads).

## 2. Responsibility of every file in `agent/`

| File | Responsibility |
|---|---|
| `main.py` | Defines the Cycls **image** (system deps, pip packages, Arabic fonts, files copied into the container), the **web/brand config** (Clerk auth, bilingual branding, colors, SEO), the three **custom tools** (`tender_search`, `tender_lookup`, `award_comps`) and their handlers (direct Supabase REST/RPC calls), the **LLM base config** (Kimi K3 via Moonshot, tool wiring, sandboxed Bash/Editor/DataBase access), the `@cycls.agent` **entrypoint** that streams the model's turn, and two extra FastAPI routes (`/cron/daily-brief`, `/email/unsubscribe`). |
| `prompt.py` | A single function, `build_prompt(gregorian_date)`, that returns the **entire system prompt**. This is the actual control flow of the agent — it is a state machine encoded in natural language, driven by what's stored in the per-user `memory/index` key. Covers onboarding, tender browsing, single-tender lookup, email subscription, and technical/financial offer-document generation. |
| `daily_brief.py` | A **non-LLM batch job**. For every subscribed user it reads their profile from the Cycls per-user DB, queries Supabase's `search_tenders` RPC directly (no model call), renders a branded Arabic RTL HTML email, and sends it via Resend. Also owns the HMAC unsubscribe-token logic and the subscription-state mutation (`set_unsubscribed`) called from `main.py`'s `/email/unsubscribe` route. |
| `skills/docx/rtl_helpers.py` | A reusable helper library for `python-docx`, copied into the container image so the agent's sandboxed Bash/Editor tools can generate correctly right-to-left, bilingual `.docx` offer documents (technical/financial reports) without hand-rolling OOXML. |
| `requirements.txt` | Dependencies needed to run `cycls run`/`cycls deploy` **locally** and to execute `daily_brief.py` outside the container. The deployed container instead builds its dependency set from `cycls.Image().pip(...)` in `main.py`. |
| `README.md` | Agent-specific setup/run/deploy instructions and a summary of the daily-brief trigger chain and storage split (Cycls per-user DB vs. read-only Supabase). |
| `.env` | Real secret values for local `cycls run`, copied verbatim into the deployed image via `image.copy(".env")`. |

_MAX_PAYLOAD_CHARS = 20_000


def _rpc_search(supabase_url, supabase_key, *, q, only_active=True,
                city="", agency="", max_rows=10, select=None, timeout=12):
    """Call the search_tenders RPC (trigram + multi-field, relevance + city ranked).
    Returns (rows, response); rows is [] on any non-200. Requires the migration
    in scraper/db/search_functions.sql to have been run."""
    import requests
    headers = {
        "apikey": supabase_key,
        "Authorization": f"Bearer {supabase_key}",
        "Content-Type": "application/json",
    }
    url = f"{supabase_url}/rest/v1/rpc/search_tenders"
    if select:
        url += f"?select={select}"
    body = {"q": q or "", "only_active": only_active,
            "city": city or "", "agency": agency or "", "max_rows": max_rows}
    r = requests.post(url, headers=headers, json=body, timeout=timeout)
    return (r.json() if r.status_code == 200 else []), r


def _num_stats(values):
    """min / median / max / count over positive numeric values (drops null/0)."""
    vals = sorted(v for v in values if isinstance(v, (int, float)) and v > 0)
    if not vals:
        return None
    return {"min": round(vals[0]), "median": round(statistics.median(vals)),
            "max": round(vals[-1]), "count": len(vals)}


def make_tender_search():
    supabase_url = os.environ.get("SUPABASE_URL", "")
    supabase_key = os.environ.get("SUPABASE_SERVICE_KEY", "")

    async def handler(args):
        keyword = (args.get("sector") or "").strip()
        place   = (args.get("region") or "").strip()
        fields = "etimad_tender_id,tender_name,agency_name,publish_date,last_offer_date,condition_booklet_price,place,detail_url"

        # Trigram + multi-field search; the RPC ranks by city → relevance → deadline.
        rows, r = _rpc_search(supabase_url, supabase_key, q=keyword,
                              only_active=True, city=place, max_rows=10, select=fields)
        if r.status_code != 200:
            return {"error": f"Supabase returned {r.status_code}", "detail": r.text[:500]}

        # Last resort: the sector matched nothing → soonest active tenders in the city.
        if not rows:
            rows, _ = _rpc_search(supabase_url, supabase_key, q="",
                                  only_active=True, city=place, max_rows=10, select=fields)

        if not rows:
            return {"tenders": [], "count": 0, "hint": "No active tenders found."}

        result = {"tenders": rows, "count": len(rows)}
        serialized = json.dumps(result, ensure_ascii=False, default=str)
        if len(serialized) > _MAX_PAYLOAD_CHARS:
            while rows and len(json.dumps({"tenders": rows, "count": len(rows)}, ensure_ascii=False, default=str)) > _MAX_PAYLOAD_CHARS:
                rows = rows[:-1]
            result = {"tenders": rows, "count": len(rows), "truncated": True}

        return result

    return handler

_LOOKUP_FIELDS = (
    "etimad_tender_id,tender_name,tender_number,reference_number,agency_name,"
    "tender_type,tender_purpose,place,branch_name,publish_date,last_offer_date,"

def make_tender_lookup():
    supabase_url = os.environ.get("SUPABASE_URL", "")
    supabase_key = os.environ.get("SUPABASE_SERVICE_KEY", "")

    async def handler(args):
        query = (args.get("query") or "").strip()
        if not query:
            return {"tenders": [], "count": 0, "found": False, "hint": "Empty query."}

        # Fuzzy search across name / agency / purpose / number — all tenders (incl. closed).
        rows, r = _rpc_search(supabase_url, supabase_key, q=query,
                              only_active=False, max_rows=5, select=_LOOKUP_FIELDS)
        if r.status_code != 200:
            return {"error": f"Supabase returned {r.status_code}", "detail": r.text[:500]}

        if not rows:
            return {"tenders": [], "count": 0, "found": False,
                    "hint": "No tender in the database matches this name or number."}

        result = {"tenders": rows, "count": len(rows), "found": True}
        serialized = json.dumps(result, ensure_ascii=False, default=str)
        if len(serialized) > _MAX_PAYLOAD_CHARS:
            while rows and len(json.dumps({"tenders": rows}, ensure_ascii=False, default=str)) > _MAX_PAYLOAD_CHARS:
                rows = rows[:-1]
            result = {"tenders": rows, "count": len(rows), "found": True, "truncated": True}

        return result

    return handler


def make_award_comps():
    supabase_url = os.environ.get("SUPABASE_URL", "")
    supabase_key = os.environ.get("SUPABASE_SERVICE_KEY", "")

    async def handler(args):
        import requests

        keyword = (args.get("keyword") or "").strip()
        agency  = (args.get("agency") or "").strip()
        if not keyword:
            return {"found": False, "hint": "Empty keyword."}

        headers = {"apikey": supabase_key, "Authorization": f"Bearer {supabase_key}"}

        # 1) comparable tenders by work-type keyword (fuzzy; + optional same agency)
        tenders, r = _rpc_search(supabase_url, supabase_key, q=keyword,
                                only_active=False, agency=agency, max_rows=80,
                                select="etimad_tender_id,tender_name,agency_name")
        if r.status_code != 200:
            return {"error": f"Supabase returned {r.status_code}", "detail": r.text[:300]}
        if not tenders:
            return {"found": False, "comparables_scanned": 0,
                    "hint": "No comparable tenders for this keyword."}

        id_list = ",".join(t["etimad_tender_id"] for t in tenders)
        name_by_id = {t["etimad_tender_id"]: (t.get("tender_name"), t.get("agency_name")) for t in tenders}

        # 2) winning amounts among those comparables
        ra = requests.get(
            f"{supabase_url}/rest/v1/tender_awards"
            f"?etimad_tender_id=in.({id_list})&role=eq.awarded"
            f"&select=etimad_tender_id,award_value&limit=300",
            headers=headers, timeout=15)
        awarded = ra.json() if ra.status_code == 200 else []

        # 3) all submitted bids among those comparables (competition spread)
        rs = requests.get(
            f"{supabase_url}/rest/v1/tender_awards"
            f"?etimad_tender_id=in.({id_list})&role=eq.submitted"
            f"&select=offer_value&limit=500",
            headers=headers, timeout=15)
        submitted = rs.json() if rs.status_code == 200 else []

        award_stats = _num_stats([a.get("award_value") for a in awarded])
        offer_stats = _num_stats([s.get("offer_value") for s in submitted])

        if not award_stats and not offer_stats:
            return {"found": False, "comparables_scanned": len(tenders),
                    "hint": "Comparable tenders found, but none have award/offer figures yet."}

        examples = []
        for a in awarded:
            if a.get("award_value"):
                nm, ag = name_by_id.get(a["etimad_tender_id"], (None, None))
                examples.append({"tender_name": nm, "agency_name": ag,
                                 "award_value": round(a["award_value"])})
            if len(examples) >= 5:
                break

        return {
            "found": True,
            "comparables_scanned": len(tenders),
            "award_value": award_stats,   # winning amounts (SAR)
            "offer_value": offer_stats,   # all submitted bids — competition spread (SAR)
            "examples": examples,
            "note": "Historical figures (SAR) from CLOSED comparable tenders. A reference range, not a guaranteed price.",
        }

    return handler

def _truthy(v) -> bool:
    return str(v or "").strip().lower() in ("1", "true", "yes")


@etimad.server.post("/cron/daily-brief")
async def _cron_daily_brief(request: Request):
    secret = os.environ.get("CRON_SECRET", "")
    if not secret or request.headers.get("X-Cron-Secret", "") != secret:
        raise HTTPException(status_code=403, detail="forbidden")
    qp = request.query_params
    result = await daily_brief.run_daily_brief(
        dry_run=_truthy(qp.get("dry_run")),
        only_user=qp.get("user") or None,
        force=_truthy(qp.get("force")),
    )
    return JSONResponse(result)

## 4. Full source — `agent/prompt.py`

```python
# Etimad — system prompt.
# Imported by main.py; shipped into the container via image.copy("prompt.py").
# Built per-turn so today's date stays fresh.
# Supabase credentials are NOT injected here — they live in the tool handler.


def build_prompt(gregorian_date: str) -> str:
    return f"""You are an Etimad tender assistant. You help users discover relevant Saudi government tenders from منصة اعتماد.

Today's date: {gregorian_date}

---

## Every turn — start here

Run `database get key="memory/index"` ONCE, then route by the FIRST rule that matches, reading top to
bottom. Every subscription state ALSO contains `status: complete`, so the `subscription:` rows are
listed first — a mid-subscription user must never fall through to the tender check.

| memory/index | Flow |
|---|---|
| empty or null | **New user** — onboarding |
| has `status: onboarding` | **Onboarding answer** — accumulate & save |
| has `subscription: awaiting_email` | **Subscription: save email** |
| has `subscription: awaiting_confirm` | **Subscription: confirm** |
| has `subscription: offered` | **Subscription: respond to offer** |
| `status: complete` with NO `subscription:` line | **Returning user** — tender check |

---

## New user — onboarding

- Ask all four questions in one message:

"أهلاً! 👋 لأساعدك في اكتشاف المناقصات المناسبة، أحتاج ٤ معلومات سريعة:

١. اسمك
٢. اسم شركتك
٣. قطاع عملك
٤. مدينتك أو منطقتك

**مثال:** محمد، شركة الأفق، مقاولات، الرياض"

- Mark that onboarding question was asked:
  `database put key="memory/index" value="status: onboarding"`

---

## Onboarding answer — accumulate and save

The four fields (name, company, sector, city) may arrive across SEVERAL messages, not
all at once. Accumulate them — NEVER re-ask for something the user already gave.

Each turn while onboarding:

1. Read what's saved so far: `database get key="memory/profile"` (may be empty).
2. Re-read the WHOLE conversation (every user message so far, not just the latest)
   and collect any of: name, company name, sector(s), city.
3. Merge: start from the saved profile and fill in any newly-provided fields.

def make_token(user_id: str, action: str) -> str:
    import base64
    sig = hmac.new(_cron_secret().encode(), f"{action}:{user_id}".encode(),
                   hashlib.sha256).hexdigest()[:16]
    uid = base64.urlsafe_b64encode(user_id.encode()).decode().rstrip("=")
    return f"{uid}.{sig}"

def verify_token(token: str, action: str) -> str | None:
    import base64
    if not _cron_secret() or not token or "." not in token:
        return None
    uid_b64, _, sig = token.partition(".")
    try:
        pad = "=" * (-len(uid_b64) % 4)
        user_id = base64.urlsafe_b64decode(uid_b64 + pad).decode()
    except Exception:
        return None
    expected = hmac.new(_cron_secret().encode(), f"{action}:{user_id}".encode(),
                        hashlib.sha256).hexdigest()[:16]
    return user_id if hmac.compare_digest(sig, expected) else None

async def _send(to: str, subject: str, html: str, unsub_url: str | None = None) -> dict:
    key = _resend_key()
    if not key:
        raise RuntimeError("RESEND_API_KEY not configured")
    import httpx
    payload = {
        "from": _email_from(),
        "to": [to],
        "subject": subject,
        "html": html,
    }
    if unsub_url:
        payload["headers"] = {
            "List-Unsubscribe": f"<{unsub_url}>",
            "List-Unsubscribe-Post": "List-Unsubscribe=One-Click",
        }
    async with httpx.AsyncClient(timeout=30) as c:
        r = await c.post(
            RESEND_URL,
            json=payload,
            headers={"Authorization": f"Bearer {key}", "Content-Type": "application/json"},
        )
        if r.status_code >= 300:
            raise RuntimeError(f"Resend {r.status_code}: {r.text[:300]}")
        return r.json()

def _subject_from_key(k: str) -> str | None:
    parts = k.split("/")
    if len(parts) < 2 or parts[1] != ".database":
        return None
    depth = EMAIL_KEY.count("/") + 1
    after = len(parts) - 2
    if after == depth:
        return parts[0]
    if after == depth + 1:
        return f"{parts[0]}:{parts[2]}"
    return None

async def _load_subscribers(only_subject: str | None) -> list[tuple[str, DB, dict]]:
    base = storage_base()
    root = _store(base)
    keys = set(await root.list_keys(glob=f"*/.database/{EMAIL_KEY}"))
    keys |= set(await root.list_keys(glob=f"*/.database/*/{EMAIL_KEY}"))
    subs = []
    for k in keys:
        subject = _subject_from_key(k)
        if subject is None or (only_subject and subject != only_subject):
            continue
        db = _user_db(subject)
        pref = await db.get(EMAIL_KEY)
        if not pref or not pref.get("enabled"):
            continue
        if not _valid_email(pref.get("email", "")):
            continue
        subs.append((subject, db, pref))
    return subs

# Main batch entry point
# ----------------------------------------------------------------------
async def run_daily_brief(
    *,
    dry_run: bool = False,
    only_user: str | None = None,
    force: bool = False,
) -> dict:
    """Called by POST /cron/daily-brief in main.py."""
    date_str = _riyadh_date()
    subs = await _load_subscribers(only_user)

    result = {
        "date": date_str,
        "subscribers": len(subs),
        "sent": 0,
        "skipped": 0,
        "failed": 0,
        "dry_run": dry_run,
    }

    previews, errors = [], []

    for user_id, db, pref in subs:
        # Idempotency — skip if already sent today
        sent_key = f"usage/daily_brief/{date_str}"
        if not dry_run and not force and await db.get(sent_key):
            result["skipped"] += 1
            continue

        # Load profile
        profile = await db.get(PROFILE_KEY) or {}
        name    = profile.get("name", "")
        company = profile.get("company", "شركتك")
        sectors = profile.get("sectors", "")
        city    = profile.get("city", "")

        if not sectors or not city:
            result["skipped"] += 1
            continue

        # Search tenders (direct Supabase — no LLM)
        tenders = search_tenders(sectors, city)

        # Build email
        try:
            html, subject = build_email(company, sectors, city, tenders, user_id, date_str, name=name)
        except Exception as e:
            result["failed"] += 1
            errors.append({"user": user_id, "error": f"render: {e}"})
            continue

        if dry_run:
            previews.append({
                "user": user_id,
                "email": pref["email"],
                "subject": subject,
                "tenders_found": len(tenders),
            })
            continue

        # Send
        try:
            unsub = f"{_public_url()}/email/unsubscribe?token={make_token(user_id, 'unsub')}"
            await _send(pref["email"], subject, html, unsub_url=unsub)
            await db.put(sent_key, {"at": _now_iso(), "email": pref["email"]})
            result["sent"] += 1
        except Exception as e:
            result["failed"] += 1
            errors.append({"user": user_id, "error": str(e)})

    if previews:
        result["previews"] = previews
    if errors:
        result["errors"] = errors

    return result

```python
"""Reusable RTL/bilingual helpers for python-docx.

Use from a script in the workspace:

    import sys; sys.path.insert(0, ".skills/docx/scripts")
    from rtl_helpers import (setup_rtl, add_heading, add_paragraph, rtl_run,
                             ltr_run, rtl_paragraph, rtl_table, is_rtl)
    from docx import Document

    doc = Document(); setup_rtl(doc)                 # Arabic doc
    add_heading(doc, "عنوان المستند", level=1)
    add_paragraph(doc, "نص عربي يُعرض من اليمين إلى اليسار.")
    doc.save("out.docx")

For an English doc, just use plain python-docx (skip setup_rtl). For bilingual,
setup_rtl(doc) then mix rtl_run / ltr_run in the same paragraph, or use a
two-column table + rtl_table().
"""
from docx.oxml import OxmlElement
from docx.oxml.ns import qn

AR_FONT = "IBM Plex Sans Arabic"   # default Arabic face (clean, full weight range)
AR_SANS = "Tajawal"                # alternate Arabic sans
EN_FONT = "Calibri"


def _apply(parent, tag, attrs=None):
    el = parent.find(qn(tag))
    if el is None:
        el = OxmlElement(tag)
        parent.append(el)
    for k, v in (attrs or {}).items():
        el.set(qn(k), v)
    return el


def is_rtl(text):
    """True if the text contains Arabic/Hebrew/etc. characters."""
    return any("؀" <= c <= "ۿ" or "ݐ" <= c <= "ݿ"
               or "ࢠ" <= c <= "ࣿ" or "ﭐ" <= c <= "﻿" for c in text)


def setup_rtl(doc, font=AR_FONT, bidi="ar-SA"):
    """Apply the document-wide RTL markers (markers 1-3). Call once per doc."""
    _apply(doc.settings.element, "w:themeFontLang", {"w:bidi": bidi})              # 1
    dd = _apply(doc.styles.element, "w:docDefaults")                              # 2
    rPr = _apply(_apply(dd, "w:rPrDefault"), "w:rPr")
    _apply(rPr, "w:rFonts", {"w:ascii": font, "w:hAnsi": font, "w:cs": font, "w:eastAsia": font})
    _apply(rPr, "w:rtl")
    _apply(_apply(_apply(dd, "w:pPrDefault"), "w:pPr"), "w:bidi")
    for section in doc.sections:                                                  # 3
        _apply(section._sectPr, "w:bidi")


def rtl_paragraph(p):
    """Mark a paragraph RTL (marker 4a). Don't set jc=right — Word mirrors it."""
    _apply(p._p.get_or_add_pPr(), "w:bidi")


def rtl_run(run, font=AR_FONT):
    """Mark an Arabic run RTL with the complex-script font (marker 4b)."""
    rPr = run._r.get_or_add_rPr()
    _apply(rPr, "w:rFonts", {"w:ascii": font, "w:hAnsi": font, "w:cs": font})
    _apply(rPr, "w:rtl")


def ltr_run(run, font=EN_FONT):
    """English run inside an RTL document — Latin font, no rtl marker."""
    rPr = run._r.get_or_add_rPr()
    _apply(rPr, "w:rFonts", {"w:ascii": font, "w:hAnsi": font})


def rtl_table(table):
    """Make table columns stack right-to-left."""
    _apply(table._tbl.tblPr, "w:bidiVisual")


# --- convenience builders (auto-direction by text) ---------------------------

def add_heading(doc, text, level=1, font=AR_FONT):
    h = doc.add_heading("", level=level)
    run = h.add_run(text)
    if is_rtl(text):
        rtl_paragraph(h); rtl_run(run, font)
    return h


def add_paragraph(doc, text, font=AR_FONT, bold=False):
    p = doc.add_paragraph()
    run = p.add_run(text); run.bold = bold
    if is_rtl(text):
        rtl_paragraph(p); rtl_run(run, font)
    else:
        ltr_run(run)
    return p


def bilingual_table(doc, rows, ar_header="العربية", en_header="English"):
    """rows: list of (arabic, english) tuples. Builds a 2-col RTL table."""
    t = doc.add_table(rows=1, cols=2); t.style = "Table Grid"
    hdr = t.rows[0].cells
    r = hdr[0].paragraphs[0].add_run(ar_header); rtl_paragraph(hdr[0].paragraphs[0]); rtl_run(r)
    r = hdr[1].paragraphs[0].add_run(en_header); ltr_run(r)
    for ar, en in rows:
        cells = t.add_row().cells
        ra = cells[0].paragraphs[0].add_run(ar); rtl_paragraph(cells[0].paragraphs[0]); rtl_run(ra)
        re = cells[1].paragraphs[0].add_run(en); ltr_run(re)
    rtl_table(t)
    return t


def validate(path):
    """Raise if RTL markers are missing in a doc that contains Arabic."""
    import zipfile
    z = zipfile.ZipFile(path)
    d = z.read("word/document.xml").decode()
    if is_rtl(d):
        st = z.read("word/styles.xml").decode()
        s = z.read("word/settings.xml").decode()
        assert "themeFontLang" in s and "<w:rtl/>" in st and "<w:bidi/>" in d, \
            "RTL markers missing — did you call setup_rtl(doc)?"
    return True

## 8. Complete agent flow

### 8.1 Actors and data stores
- **Cycls chat agent** (`main.py` + `prompt.py`) — the interactive, per-message LLM turn.
- **Cycls per-user DB** — a key/value store scoped to the authenticated user (via Clerk),
  accessed in the prompt through `database get`/`database put` "tool calls" the model
  issues itself (this is Cycls' built-in `DataBase` tool, listed in `allowed_tools`).
  Keys used: `memory/index`, `memory/profile`, `memory/current_tender`, `memory/email`,
  `usage/daily_brief/<date>`.
- **Supabase** — read-only from the agent's perspective; the source of truth for tender
  data, populated separately by `scraper/`. Reached through the `search_tenders` and
  `tender_awards`/`tender_search` RPC/REST endpoints.
- **daily_brief.py** — a separate, non-interactive batch process triggered by a signed
  HTTP POST from GitHub Actions, not by chat messages.

### 8.2 Turn-by-turn flow inside the chat agent

```
User message arrives
   │
   ▼
main.py: etimad(context)
   │  - no-op if context.messages is empty
   │  - build system = build_prompt(today's Riyadh date)
   │  - stream _llm_base.system(system).run(context=context)
   ▼
Model's FIRST action every turn (mandated by prompt.py):
   database get key="memory/index"      (read ONCE)
   │
   ▼
Route by the FIRST matching rule (checked top-to-bottom):
   ┌─────────────────────────────────────────────────────────────────┐
   │ memory/index empty/null              → New user: onboarding      │
   │ contains "status: onboarding"        → Accumulate onboarding answer│
   │ contains "subscription: awaiting_email"   → save email step      │
   │ contains "subscription: awaiting_confirm" → confirm email step   │
   │ contains "subscription: offered"     → respond to brief offer    │
   │ "status: complete", no subscription: → Returning user: tender check│
   └─────────────────────────────────────────────────────────────────┘
```

### 8.3 First message → onboarding
1. `memory/index` is empty → the model asks all 4 onboarding questions in one Arabic
   message (name, company, sector, city) and writes `memory/index = "status: onboarding"`.
2. On each subsequent turn while in that state, the model:
   - reads `memory/profile` (partial data from earlier turns, if any),
   - re-scans the *whole* conversation for any of the 4 fields,
   - merges new answers into the saved profile (never overwriting a known field with blank),
   - writes the merged object back to `memory/profile`,
   - if all 4 fields are now present: sets
     `memory/index = "status: complete; subscription: offered"`, confirms save, runs
     the tender check inline, and appends the daily-email offer to the same message;
   - if fields are still missing: asks only for what's missing.

### 8.4 Memory read/write pattern
- `memory/index` is the **state pointer** — a short semi-structured string
  (e.g. `"status: complete; subscription: awaiting_confirm; email: x@y.com"`), read
  exactly once per turn and never re-read afterward ("trust your own writes").
- `memory/profile` holds the **durable user profile** (JSON: `name`, `company`,
  `sectors`, `city`).
- `memory/current_tender` holds the **tender under active discussion**, filled in by
  `tender_lookup` results and extended field-by-field during report generation
  (`contract_type`, `company_profile`, `team`, `certifications`).
- `memory/email` holds the **subscription record** (JSON: `enabled`, `email`,
  optionally `unsubscribed_at`), the only key `daily_brief.py` reads/writes directly
  (it never touches `memory/index`).
- `usage/daily_brief/<YYYY-MM-DD>` is a per-day idempotency marker so a subscriber
  never gets two briefs the same day even if the cron route is hit twice.

### 8.5 Returning user → tender search
1. Reads `memory/profile` for `sectors` + `city`.
2. If `city` is a specific place, calls `tender_search` once (sector + region).
   If `city` is broad ("السعودية"/"المملكة"), asks the user to narrow or confirm a
   full-Kingdom search, which triggers one `tender_search` call per major region
   (الرياض، جدة، مكة المكرمة، المدينة المنورة، الدمام، أبها).
3. `tender_search` → `main.py:make_tender_search()` → POSTs to Supabase's
   `search_tenders` RPC with `only_active=true`, ranked by city-match then relevance
   then deadline; if the sector matches nothing it retries with an empty query
   (soonest active tenders in the city) as a fallback.
4. Model renders up to 5 results as a fixed-column Arabic markdown table, then offers
   to generate a technical or financial report for any of them.

### 8.6 Specific-tender lookup & report generation
- A request about one named tender (or "this tender") routes to `tender_lookup`
  instead — `main.py:make_tender_lookup()`, which fuzzy-searches the *full* tenders
  table (open + closed), returns rich detail fields, and on a hit the model saves
  `memory/current_tender` so later turns ("this tender", a price question, a report
  request) don't need to re-identify it.
- A bid/price question triggers `award_comps` (`main.py:make_award_comps()`), which
  finds comparable past tenders by keyword, then pulls `award_value` (winning bids)
  and `offer_value` (all submitted bids) from `tender_awards`, returning min/median/max
  stats plus a few named examples — used to ground pricing, never invented.
- Full offer generation (`العرض الفني` / `العرض المالي`) is gated behind collecting 4
  info groups conversationally (contract type, company profile, team, certifications),
  stored incrementally into `memory/current_tender`. Once complete, the model writes a
  Python script using the sandboxed **Editor** tool and runs it with **Bash**
  (`python3 <script>.py`), producing two separate `.docx` files under `reports/`
  (`tender-<id>-technical.docx`, `tender-<id>-financial.docx`), using
  `skills/docx/rtl_helpers.py` for correct RTL/bidi formatting — never raw OOXML.
  Financial figures are strictly forbidden in the technical file; the financial
  file must call `award_comps` for its pricing analysis and add 15% VAT.

### 8.7 Daily email subscription (in-chat)
A 3-step handshake tracked entirely in `memory/index`:
```
offered → awaiting_email → awaiting_confirm → complete (memory/email written)
```
- **offered**: user answers the post-onboarding offer; yes → ask for email and set
  `awaiting_email`; no/other → clear back to plain `status: complete`.
- **awaiting_email**: the user's very next message is treated as their email address;
  it's read back for confirmation and staged (not yet saved) as `awaiting_confirm`
  with the address embedded in the index string.
- **awaiting_confirm**: on confirmation, the model finally writes
  `memory/email = {"enabled": true, "email": "..."}` and clears the index back to
  `status: complete`. A correction at this step loops back to `awaiting_email`.
- **Unsubscribe** (via chat) sets `memory/email.enabled = false` directly, at any time.
- **Unsubscribe** (via emailed link) instead hits the stateless HTTP route
  `GET /email/unsubscribe?token=...` in `main.py`, which calls
  `daily_brief.verify_token()` (HMAC-signed, keyed by `CRON_SECRET`) then
  `daily_brief.set_unsubscribed()` — no LLM involved.

### 8.8 Daily brief batch run (no LLM)
```
GitHub Actions "Etimad Daily Brief" (workflow_run after "Etimad Scrape" succeeds,
or workflow_dispatch)
   │  POST {ETIMAD_URL}/cron/daily-brief?dry_run=&force=&user=
   │  header: X-Cron-Secret: <CRON_SECRET>
   ▼
main.py: POST /cron/daily-brief
   │  - 403 unless X-Cron-Secret matches CRON_SECRET
   │  - calls daily_brief.run_daily_brief(dry_run, only_user, force)
   ▼
daily_brief.run_daily_brief()
   │  - _load_subscribers(): scans the Cycls volume for every */.database/memory/email
   │    key across ALL users, keeps only enabled + validly-formatted addresses
   │  - for each subscriber:
   │      - skip if usage/daily_brief/<today> already exists (unless force/dry_run)
   │      - read memory/profile; skip if sectors or city missing
   │      - search_tenders(sectors, city) → direct Supabase RPC call (no LLM)
   │      - build_email(...) → branded Arabic RTL HTML + subject
   │      - dry_run → append to previews, don't send
   │      - else → _send() via Resend, then write usage/daily_brief/<today> marker
   ▼
JSONResponse: {date, subscribers, sent, skipped, failed, dry_run, previews?, errors?}
```

## 9. Tool definitions (LLM-callable, defined in `main.py`)

| Tool | Purpose | Input | Backing call | Notes |
|---|---|---|---|---|
| `tender_search` | Browse active tenders by sector + city | `sector` (required), `region` (required) | POST Supabase RPC `search_tenders` (`only_active=true`, ranked city → relevance → deadline) via `_rpc_search` | Falls back to an empty-query search (soonest active in city) if the sector matches nothing. Payload capped at 20,000 chars via row truncation. One call per turn unless doing a full-Kingdom sweep. |
| `tender_lookup` | Look up ONE specific tender by name/number, incl. closed ones | `query` (required) | POST Supabase RPC `search_tenders` (`only_active=false`, richer field set) | Ignores city; fuzzy trigram match across name/agency/purpose/number. Returns `found: false` rather than guessing when nothing matches. |
| `award_comps` | Bid-pricing comparables from past awarded tenders | `keyword` (required), `agency` (optional) | 1) RPC `search_tenders` for comparable tenders (up to 80), 2) REST GET on `tender_awards` filtered `role=eq.awarded` for winning amounts, 3) REST GET on `tender_awards` filtered `role=eq.submitted` for the competition spread | Computes min/median/max/count via `_num_stats`; returns up to 5 concrete examples. Used to ground bid-price questions and the financial-offer's "التحليل المالي" section. |

Besides these three custom tools, the LLM is also wired to Cycls' built-in
`Bash`, `Editor`, and `DataBase` tools (`.allowed_tools(["Bash", "Editor", "DataBase"])`,
`.sandbox(network=True)`):
- **DataBase** → the `database get`/`database put` calls that implement all memory
  reads/writes described in §8.4 (this is not a Python function in this repo; it's a
  Cycls-provided capability the model invokes directly per the prompt's instructions).
- **Editor** / **Bash** → used only for report generation: writing a Python script that
  uses `python-docx` + `rtl_helpers.py` and executing it to produce `.docx` files
  under `reports/` inside the sandbox's `/workspace` volume.

## 10. Memory architecture — index vs. profile vs. other keys

| Key | Shape | Written by | Lifecycle |
|---|---|---|---|
| `memory/index` | Short string, semicolon-separated fields, e.g. `"status: complete; subscription: awaiting_confirm; email: x@y.com"` | Chat model only | The **state machine pointer** — read once at the top of every turn to decide which prompt section applies. Transient/derived; nothing outside the prompt depends on its exact grammar. |
| `memory/profile` | JSON: `{name, company, sectors, city}` | Chat model during/after onboarding | The **durable identity/preferences record**. Read by `tender_search`/browse flow and by `daily_brief.py` for every subscriber. Merge-only updates — a field is never blanked once set. |
| `memory/current_tender` | JSON: starts as `{id, number, name}` from `tender_lookup`, later extended with `{contract_type, company_profile, team, certifications}` | Chat model | The **active-tender / offer-drafting scratchpad**. Overwritten wholesale (read-merge-write) whenever the discussed tender changes or a new offer-info field is collected. |
| `memory/email` | JSON: `{enabled: bool, email: str, unsubscribed_at?: iso}` | Chat model (subscribe/unsubscribe) AND `daily_brief.py` (`set_unsubscribed`, via the unsubscribe link) | The **subscription record** — the only key the batch job reads/writes directly; it never touches `memory/index`. |
| `usage/daily_brief/<YYYY-MM-DD>` | JSON: `{at: iso, email: str}` | `daily_brief.py` only | Per-day **idempotency marker** preventing duplicate sends; ignored by the chat model entirely. |

Design point worth calling out: `memory/index` and `memory/profile` are
**intentionally split** — `index` is disposable conversational state (what step of a
flow we're in) that only the LLM interprets, while `profile` is the stable business
data that a separate, non-LLM process (`daily_brief.py`) also depends on. This lets
the batch job stay simple (`profile` + `email`, no state-machine parsing) even though
the chat flow's bookkeeping (`index`) is much chattier.

Supabase, by contrast, holds **no per-user state at all** — it is a read-only tender
catalog (`active_tenders` view / full tenders table / `tender_awards`) written
exclusively by the separate `scraper/` codebase.

## 11. Scheduled jobs & GitHub Actions workflows

| Workflow | Trigger | What it does | Relation to the agent |
|---|---|---|---|
| **`scrape.yml`** ("Etimad Scrape") | `schedule: "0 3 * * *"` (03:00 UTC = 6am Saudi) + manual dispatch | Probes for WAF blocking, then runs `scraper/daily.py` to incrementally scrape new/active tenders into Supabase | Upstream data dependency — the agent's tools query whatever this leaves in Supabase. |
| **`daily-brief.yml`** ("Etimad Daily Brief") | `workflow_run` on `["Etimad Scrape"]` completion (only fires if the scrape succeeded) + manual `workflow_dispatch` (with `dry_run`, `force`, `only_user` inputs) | `curl -X POST ${ETIMAD_URL}/cron/daily-brief` with header `X-Cron-Secret: ${CRON_SECRET}`, passing `dry_run`/`force`/`user` as **query params** | This is the **only** trigger for `daily_brief.py`'s `run_daily_brief()` — it calls straight into the `/cron/daily-brief` FastAPI route added in `main.py`. Requires repo secrets `ETIMAD_URL` and `CRON_SECRET`. |
| **`awards-scrape.yml`** ("Etimad Awards Scrape") | `schedule: "0 6 * * 1"` (Monday 06:00 UTC) + manual dispatch | Runs `scraper/parallel.py` in `MODE=awards` to capture applicant/winner data for tenders recently marked "تم اعتماد الترسية" | Feeds `tender_awards`, the table `award_comps` reads from — indirectly powers the financial-offer pricing analysis. |
| **`parallel-scrape.yml`** ("Parallel Scrape (Bright Data)") | Manual `workflow_dispatch` only | Sharded, proxied full-history backfill scrape (`scraper/parallel.py`), with a smoke-test mode and checkpoint caching | Not on a schedule; used for large one-off backfills, not part of the daily pipeline. |
| **`probe-pagination-cap.yml`** ("Probe Pagination Cap") | Manual `workflow_dispatch` only | One-off feasibility probe (`scraper/probe.py`) to characterize Etimad's pagination limits before committing to a full backfill | Diagnostic tool, unrelated to the agent's runtime behavior. |

**Recurring pipeline, end to end:**
```
03:00 UTC daily   scrape.yml        → scraper/daily.py        → Supabase updated
      (on success) ──────────────▶ daily-brief.yml            → POST /cron/daily-brief
                                                                 → daily_brief.run_daily_brief()
                                                                 → Resend sends each subscriber
                                                                   their personalized digest
Mon 06:00 UTC     awards-scrape.yml → scraper/parallel.py (awards mode) → tender_awards updated
```

There is no scheduled job that touches the *chat* half of the agent directly — the
only server-side scheduled interaction is the daily-brief POST. The chat agent itself
is invoked purely by inbound user messages through the Cycls web app (Clerk-authenticated).
